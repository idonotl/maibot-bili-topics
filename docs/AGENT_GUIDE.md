# B站话题与转写：用户与 Agent 接入指南

## 1. 安装前检查

先阅读 README、`_manifest.json`、`config.example.toml` 和配置参考。确认宿主版本、Python 环境、实际插件目录、数据目录和模型配置。不要收集或输出密钥，不从使用者原配置复制令牌进 Git。

本指南对应 0.6.0。先核对实际部署的宿主版本和已启用的配置。

## 2. 本插件做什么

公开素材、可选语音转写、关键帧分析与后台深看。

先验证授权会话和基础工具，再逐项开启深看功能。

管理员、私聊和群名单默认不含任何真实用户。配置类要求非空机器人号时，必须填部署者自己的机器人号后才能加载。启用状态和 dry_run/shadow_mode 是独立概念：前者控制启动，后者控制是否实际生效或提交任务。

### 视频资料与深看

- 基础工具包括 `bili_video_probe`、`bili_search`、`bili_trending`。标题、简介和弹幕分别提供元信息及观众反应。
- `bili_transcript` 将有权访问的音轨交给本地 faster-whisper。安装 `requirements-transcript.txt` 后提供 CTranslate2 格式的模型目录，设置 `transcript_model_dir` 与 `transcript_enabled=true`。CPU 可使用 `int8`；模型文件单独准备。
- `bili_frames` 按时长和弹幕热点取样，PyAV 解码，Pillow 压缩，宿主模型生成画面描述。设 `frames_enabled=true`，确认宿主 `utils` 模型能接收图片输入。截图只反映抽样时刻，弹幕不能作为画面事实。
- `browse_enabled=true` 后可启用 `browse_deep_watch`，后台按开关完成转写与抽帧。同一视频可以复用缓存。表达学习通过可选的 `local.whale-style.auto_learn` 联动；独立安装这个仓库即可使用视频功能。
- 若匿名无法获取部分媒体轨，可按自己的访问权限使用本地 SDK 数据目录中的 `bili-cookie.json`，结构为 `{"cookies": {"SESSDATA": "<本地值>"}}`。公开版本只将 Cookie 发往 B 站 API 的 HTTPS 请求。切勿提交真实文件。
- `local.bili-topics.pick_topic` 可供主动搭话使用，`local.bili-topics.learning_material` 可供表达学习取缓存。两者都不会直接发送 QQ 消息。

## 3. 数据与边界

插件 ID：`local.bili-topics`。不要自行更改 ID。数据目录由 SDK 提供，路径不可硬编码。聊天内容、提炼记忆、关系状态和转写都可能是私人数据；部署者需自行配置保留周期与访问权限。不要把数据目录、模型权重、缓存、日志和真实配置上传源码仓库。

升级前备份；恢复数据前停止写入，核对 schema 和插件 ID。恢复是覆盖，不是自动合并。关掉插件不会自动删除数据库。

## 4. 模型、网络与工具

模型通过宿主别名选择，在管理页核对存在性。学校、OpenAI 兼容服务或其他供应商是否可用取决于宿主配置；本仓库不提供 API 密钥。模型超时、配额不足、权限不足分别检查，不能声称某次调用已成功。

QQ 收发由外部适配器承担。需要 QQ 的功能必须配置适配器并由本人扫码，不由 Agent 代登录。自动功能先限定小范围，避免无人看守时向大群测试。

已声明入口（具体参数、返回结构和可见性以各 Python 文件及 `webui.json` 为准；不是所有 API 都对其他插件公开）：

- `API`：`pick_topic`（plugin.py）
- `API`：`status`（plugin.py）
- `Tool`：`bili_video_probe`（plugin.py）
- `Tool`：`bili_search`（plugin.py）
- `Tool`：`bili_trending`（plugin.py）
- `Tool`：`bili_my_topics`（plugin.py）
- `Tool`：`bili_browse`（plugin.py）
- `Tool`：`bili_share_session`（plugin.py）
- `Tool`：`bili_browse_status`（plugin.py）
- `Tool`：`bili_transcript`（plugin.py）

跨插件连接不能假定短名唯一，优先用稳定全名。只有 `public=True` 的 API 才可跨插件调用，并须声明 `api.call` 能力。不要替其他插件扩大权限来消除报错。

## 5. 上线步骤

1. 将源代码放在插件独立目录；不要多套一层解压文件夹。
2. 依赖安装到宿主 Python，复制示例配置并填写自己的账号和白名单。
3. 在模型配置中建立需要的别名。无相关能力时保持对应开关关闭。
4. 启动插件，检查 manifest、依赖和配置错误；先查询状态，不发测试 QQ 消息。
5. 在隔离 WebUI 或用户同意的私聊验证一次；观察成功发送与队列状态的区别。
6. 用户确认后再启用目标群和自动行为。保留恢复配置和数据备份。

## 6. 验收

运行 README 的测试命令，记录通过、失败、跳过数。单元测试是本地合成数据，不保证外部 API 或 QQ 实时可用。不得通过删除失败断言伪造通过。宿主契约测试缺少源码时设置 `MAIBOT_HOST_ROOT`，再运行；保留跳过说明。

实际验收检查：插件 ready；模型别名可用；白名单只含授权对象；本机无日志泄露；关闭插件后宿主可正常聊天。遇到联网失败，不更改系统代理、账号设备或清理登录数据来试错。

## 7. 故障排查

| 症状 | 检查 |
|---|---|
| 不显示插件 | 仓库根层 manifest、宿主扫描目录、版本范围、导入依赖 |
| 配置错误 | 真实机器人号、空白名单项、字段边界与版本 |
| 没反应 | enabled、试运行、授权范围、已过滤的消息是否进入宿主 |
| 模型失败 | 宿主模型别名、额度、模型工具能力与超时日志 |
| 不主动发言 | 空闲、静默、冷却、日上限、等待真人新消息、QQ在线与Planner决定 |
| 记不住 | 是否已提炼、当前场景/用户、词法检索是否命中、衰减及额度 |
| B站失败 | 具体接口、限制、资料范围、可选模型目录及依赖；不要把弹幕当字幕 |

## 8. Agent 修改与报告要求

先读实际实现，不假定示例是 API。禁止用正式聊天做无授权回归；禁止提交真实 config.toml、sqlite、日志或登录状态。新增配置同步文档和示例，迁移 schema 需备份与版本校验，异步热路径避免同步阻塞。

交付时写明：修改文件、依赖和环境要求、配置步骤、测试结果、外网/QQ未验证项、如何关闭和回滚。对于不确定的推断明确标记，不把尝试说成成功。

## 本插件的机制与实际使用

默认关闭整体、自动浏览、深读和转写；首次先只启用需要的基本工具。工具名为 `bili_video_probe`、`bili_search`、`bili_trending`，是否被模型选择取决于宿主的工具发现和模型能力，不是安装后每句必调。

工具接收 BV号、B站视频链接和支持的短链文案；平台分享卡片是否保留链接依赖适配器，插件不修改适配器。热门内容按 interests 过滤；主动浏览按 browse_keywords（空时用 interests）检索。网络请求受接口可用性、限流与代码中的体积和时长限制影响。

深读使用简介和弹幕样本，并由 summary_model 生成摘要。弹幕是观众反应，不能冒充视频原话；标题和观众反应也不保证代表完整内容。`pick_topic` 复用后台预热，避免阻塞主动搭话5秒等待预算。

本地语音转写单独启用 `transcript_enabled=true`。要求兼容的 faster-whisper、PyAV/CTranslate2 和本地模型文件，填写 `transcript_model_dir`，默认 CPU/int8。默认最多20分钟视频、硬超时600秒；长任务可能在后台继续。音轨下载默认上限40MiB，清理操作无法在强杀后得到保证。转写文本也可能包含敏感内容，按保留周期清理。模型权重和音轨不进入源码仓库。

转写不是 B站官方字幕下载，不保证所有视频都可访问。CPU测试不代表 GPU环境经过验证。GPU额外依赖应参考安装的 CTranslate2/faster-whisper 官方版本说明，不照搬固定CUDA组合。当前版本不分析视频画面，对图表、表情、游戏操作的理解有限。外网读写和 ASR在本次开源整理中未做真实端到端验收。
